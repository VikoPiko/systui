# SysTUI architecture decisions

Document actual choices as they are made. Do not state proposals as implemented decisions.

| ID | Status | Decision | Reason | Implications |
| --- | --- | --- | --- | --- |
| ADR-001 | Proposed | Native Rust binary + Ratatui/Crossterm | Lightweight cross-platform terminal UI | Verify dependency/toolchain compatibility. |
| ADR-002 | Proposed | Persistent targeted sysinfo collector | Cheap and portable CPU/memory/process data | Delta metrics require warm-up. |
| ADR-003 | Proposed | Read-only by default, process termination gated | Avoid destructive surprises | Dedicated action layer and identity recheck. |
| ADR-004 | Proposed | Integrations optional and independently scheduled | Core app must remain responsive | Explicit enablement and timeouts. |
| ADR-005 | Accepted | `ratatui 0.30` (`default-features=false`, `crossterm` feature); use only the `ratatui::crossterm` re-export | One crossterm (0.29.0) in the tree | Never add `crossterm` as a direct dependency. |
| ADR-006 | Accepted | `ratatui::try_init`/`restore` plus a `Drop` guard for terminal lifecycle | Panic hook restores the terminal; guard covers `?` returns | Release profile keeps `panic = "unwind"`. |
| ADR-007 | Accepted | lib + bin split; no async runtime; blocking `event::poll` loop with dirty-flag redraw | Testability; no idle redraws; fewer deps | Collector worker thread (M1) will feed the loop via a std channel. |
| ADR-008 | Accepted | Unknown config keys ignored silently; out-of-range values are hard errors | Forward compatibility vs. actionable validation | Typos in key names are not reported. |
| ADR-009 | Accepted | Theme `auto` resolves to dark | Terminal background can't be queried reliably | Documented limitation. |
| ADR-010 | Accepted | Collector = one worker thread owning `System`/`Networks`/`Disks`; publishes into a last-value-wins slot; UI polls it every 100 ms and sends `RefreshNow`/`Watch` via mpsc | Bounded memory, no async runtime, UI never calls the OS | Up to 100 ms display latency for a new snapshot. Process kill is the only OS call made on the UI thread (user-triggered, one short-lived PID lookup). |
| ADR-011 | Accepted | Pause freezes the display and drops samples taken while paused (histories get a gap); on resume the latest snapshot is applied | Simple, never shows multi-second-old rates as current | Spec allows either; documented. |
| ADR-012 | Accepted | Windows processes with 0 working set are `restricted` (rss/cpu = unknown, shown `denied`); Windows `status` is `—` | sysinfo gives 0 / hard-coded `Run` when access is denied; displaying them would be invented data (observed ~140 of 333 processes unelevated) | Linux kernel threads (legitimately 0 RSS) are NOT flagged. |
| ADR-013 | Accepted | Uptime comes from `sysinfo` (monotonic tick count) | PowerShell `now - LastBootUpTime` was off by exactly 3600 s across a DST change; the OS monotonic value is the trustworthy one | Does not count time spent suspended on some platforms. |
| ADR-014 | Accepted | Terminate requires typing the PID + Enter (or `y` if `confirm_terminate=false`); Windows has only a forced kill (no graceful API in sysinfo); Linux offers SIGTERM first and `f` for SIGKILL with fresh confirmation | "Not killable by one mistaken key"; honest about platform capability | Protected list is best-effort (name based), not a guarantee. |
| ADR-015 | Accepted | Command line fetched lazily for the inspected process only, hidden until `e` | Spec: no routine cmdline collection; secrets often live in args | Details show "loading…" for up to one sample. |
| ADR-016 | Accepted | Overview network = sum over non-loopback interfaces | No single "selected" interface on Overview | May double count virtual adapters (e.g. Hyper-V vEthernet bridging); labelled on the Network tab. |
| ADR-017 | Accepted | ASCII border set is custom (`+ - \|`); ratatui's `PLAIN` is still box-drawing | Found by test: it leaked Unicode glyphs in ASCII mode | — |
| ADR-018 | Accepted | Default 1 s refresh kept even though it costs ~2.8 % of one core on Windows (330 procs); documented, tunable via `--refresh-ms` | Spec fixes the default; the cost is `sysinfo`'s process/network enumeration (~28 ms + ~14 ms per refresh), not our code | Spec's <1 % target is only met at 5 s. Revisit: tab-aware refresh (skip process refresh on Network/Storage), slower network cadence. |
| ADR-019 | Accepted | `snapshot` omits hostname, usernames, cmdlines, env, addresses; home dir -> `~`, other profiles -> `<user>`; `null` for unavailable | Spec §5.8/§12 privacy defaults | No `--include-hostname` option yet. |
| ADR-020 | Accepted | `doctor` and `snapshot` use a `say!` macro that ignores write errors | `println!` panicked on `systui doctor \| head` (found by hand, regression-tested) | — |
| ADR-021 | Accepted | Palette is a fixed enum of commands; text is only used for fuzzy-matching titles | Spec: never parse or run shell text | Adding a command means adding an enum variant. |
| ADR-022 | Accepted | `x` export writes `systui-process-<pid>-<unix>.json` to the current dir with create-new semantics | Small, user-triggered, no overwrite; done on the UI thread | A blocked/slow working directory could stall one keypress. |
| ADR-023 | Accepted | Install scripts never edit PATH without consent (`-AddToPath`/prompt on Windows; `install.sh` only prints the line) | Spec §12/§15 | — |
| ADR-024 | Accepted | Optional modules live on their own threads, are created only when the Dev tab is first opened, and poll only while it is visible (`Visible(bool)` command) | Spec: lazy detection, no polling of unused modules, never block Overview | First Dev-tab visit shows "checking…"; leaving the tab freezes module data (shown with its age/STALE). |
| ADR-025 | Accepted | External programs go through `util::exec::run`: fixed argv, `CREATE_NO_WINDOW` on Windows, kill at deadline, 256 KiB cap per stream | Spec §9.3/§12; avoids console flashes over the TUI | No shell is ever used; output is treated as untrusted and sanitized. |
| ADR-026 | Accepted | Docker via the CLI with tab-separated Go templates (not `{{json .}}`) | `json .` includes full label sets (can carry secrets); templates request only needed fields | Output format depends on the installed `docker` honoring `--format`; malformed lines are counted, not guessed. |
| ADR-027 | Accepted | Module polls return `Result<T, ModStatus>`; on failure the worker republishes the last good data with the error status | UI can show "error + last good data (stale)" instead of blanking | Data may be older than the status suggests; the panel says so. |
| ADR-028 | Accepted | `nvml-wrapper` 0.13 (runtime `libloading`), not `nvidia-smi` | Spec names it; no per-poll process spawn | +~16 MiB RSS when the GPU module runs; NVML retry only every 15th poll when absent. |
| ADR-029 | Accepted | Process families match whole name tokens (split on non-alphanumerics, `.exe` stripped), first configured family wins | Substring matching would mislabel (`gitkraken` as `git`) | Names like `nodemon-helper` do not match `node`; add aliases for such cases. |
| ADR-030 | Accepted | The earlier-proposed tab-aware CPU optimisation was NOT implemented in M4 | Not requested explicitly; it changes update semantics per view | Default 1 s refresh still costs ~2.7–2.8 % of a core (see ADR-018). |
| ADR-031 | Accepted | Collector "needs": each sample refreshes only what the visible tab shows; skipped data is carried forward but flagged `processes_fresh`/`network_fresh = false`, and views show "Refreshing…" instead of it | Measured: processes ≈ 26 ms, networks ≈ 11 ms per refresh; Storage/Services/Network tabs drop from ~2.7 % to 0.5–0.9 % | History gets a gap for skipped data; switching tabs costs ~0.5 s of "warming up" (baselines are reset on resume so no multi-second average is shown as current). |
| ADR-032 | Accepted | Selective per-PID refresh was rejected | Measured 36 ms for the 171 readable PIDs vs 27 ms for all processes | Overview/Processes/Dev stay at the `sysinfo` floor (~2.7 % at 1 s). |
| ADR-033 | Accepted | Health checks are loopback-only: IP literals and `localhost` only (no DNS), `allow_lan` adds private ranges, public never; `http://` only; no credentials; query string never displayed | Spec §5.6/§12: local-only, no surprise network calls, no secrets | No TLS means no `https://` health endpoints; use a `tcp` check. A check that must reach a hostname cannot be expressed. |
| ADR-034 | Accepted | HTTP checks are hand-written (status line only) over `std::net` | Avoids an HTTP/TLS dependency for a one-line need | Only HTTP/1.x status lines are understood; redirects are not followed (3xx counts as healthy). |
| ADR-035 | Accepted | Health worker runs continuously once enabled (unlike Dev modules) and runs checks sequentially, each bounded by its timeout | Alerts depend on it | Many slow/failing checks delay later ones (max 32 checks, ≤10 s each). |
| ADR-036 | Accepted | Alert engine is pure and time-injected; sustained + hysteresis + cool-down; unknown never raises or clears; evaluated on every sample even when the display is paused | Spec §7 (hysteresis, cool-down, no alerts from missing data) and testability | Container-exit alert skipped (see TASKS). |
| ADR-037 | Accepted | "What changed?" keeps a ring of 40 light snapshots at most every 5 s, only from fresh process lists | Bounded (~1 MB), session-only per spec §5.8 | Cannot see processes that start and exit between two stored snapshots. |
| ADR-038 | Accepted | Tree mode builds the forest from `parent` pids but rejects a parent that started after its child and survives cycles/self-parents; disabled while a text/family filter is active | Parent PIDs are reused; a filter would otherwise hide ancestors and make indentation lie | Tree is paused (with a title note) while filtering. |
| ADR-039 | Accepted | Listening sockets via `netstat -ano` / `ss`, run once on demand in a throwaway thread; TCP "listening" is recognised by foreign port 0, not by the (localized) state word | No unsafe FFI/extra crates; never polled; works on non-English Windows | Output capped at 4 MiB (flagged `truncated`); Linux owner pid needs privileges for other users' sockets. |
| ADR-040 | Accepted | Per-process I/O uses sysinfo's per-refresh deltas divided by time since the previous PROCESS refresh; first sample after enabling is `None` | Deltas are only valid relative to the last refresh that included I/O | Windows counts all I/O (incl. network/pipes), documented. |
| ADR-041 | Accepted | Sensors are read by a platform adapter every 10 s; Windows battery uses one `unsafe` call to `GetSystemPowerStatus` (via the `windows` crate version `sysinfo` already pulls in, one extra feature); no WMI | No unprivileged Windows CPU-temperature API; WMI/`sysinfo` "component" feature is heavy and usually needs admin | Windows shows temperatures as unavailable with the reason; Linux sysfs paths are untested on a real machine. |
| ADR-042 | Accepted | Recording: `enabled` is permission, Ctrl+R is the trigger; writer thread + bounded queue (64) that drops and counts; retention by count/size/age limited to `systui-*.jsonl` in the recordings dir | Spec: "no background recorder by default"; UI must never stall on disk | Lines can be dropped under a stalled disk (counted in the stop notice). |
| ADR-043 | Accepted | Snapshot/recording documents gained `processes_fresh`, `network_fresh`, `sensors`; `process_count` became nullable; schema_version stays 1 | Additive for consumers; stale values must not be exported as live | Consumers must treat `process_count: null` as "not sampled". |
| ADR-044 | Accepted | Docker mutating commands live in `actions/docker.rs` and are limited to `stop`/`restart` by id after re-reading the container; `allow_actions` defaults to false; the confirmation is the typed container name | Same principle as process termination: one gated place, deliberate confirmation, identity re-validation | No `rm`/`kill`/`exec`/`prune` exists anywhere. A timeout kills only the CLI; the engine may still complete the operation (the message says so). |
| ADR-045 | Accepted | Docker logs are fetched on demand in a throwaway thread, merged by `--timestamps` prefix, ANSI-stripped + sanitized, shown only in the overlay | Logs often contain secrets and escape codes | Lines without a timestamp prefix sort by their first token. |
| ADR-046 | Accepted | Compose grouping requests exactly one label via a Go template (`com.docker.compose.project`) and sorts containers by (project, name) | Spec forbids pulling full label sets (secrets) | Selection index depends on that sort order. |
| ADR-047 | Accepted | SSH: allowlist + typed per-host per-session consent (not persisted), system `ssh` only, `BatchMode`, `StrictHostKeyChecking=yes`, `ClearAllForwardings`, `--` before host, fixed script, polls only while the Services tab is visible | Spec §5.6 P2: existing keys/agent, explicit allowlist, user consent, no daemon, no stored credentials | New host keys must be trusted by the user with `ssh` first; remote must be Linux with `/proc`; no alerts on remote hosts. |
| ADR-048 | Accepted | Palette ranking: a contiguous match outranks any scattered subsequence | "record" ranked "Reverse process sort order" first (found by a test) | Titles must contain the typed text to rank high. |
| ADR-049 | Accepted | `util::exec` reads output into shared buffers and waits for pipe EOF only for a 1.5 s grace after the child exits; on Unix each child gets its own process group and a timeout `killpg`s it (new direct dependency: `libc`, unix only) | Found on Linux: killing `sh -c 'sleep 60'` left `sleep` holding our pipe and `run` blocked for the full 60 s. A daemonised grandchild must never stall the UI or a worker | A helper that outlives its parent can still deliver partial output after the grace; output written after the grace is dropped. |
| ADR-050 | Accepted | Linux: userland threads reported by `sysinfo` are skipped (kernel threads are kept) | Threads appeared as processes (same RSS repeated), inflating counts and family memory sums | Matches `ps -e` (42 vs 43 on the test box). |
| ADR-051 | Accepted | Linux: when `comm` is 15 characters, the real name is recovered from the executable name or the first two argv entries and cached per process identity; health `process` checks use the same resolver and also accept a configured long name whose first 15 characters equal the truncated comm | The kernel truncates `comm`; names like `elastic-otel-collector` were unmatchable by families, health checks and exports | If neither exe nor cmdline is readable the truncated name is shown. |
| ADR-052 | Accepted | Unix: mount points that are not directories (single-file bind mounts) are not listed as volumes; the check is not done on Windows | `/mnt/wslg/versions.txt` etc. cluttered the list; a `stat` on a dead Windows network drive could block | Counted in the "N volume(s) hidden" note. |
| ADR-053 | Accepted | `scripts/pty_smoke.py` drives the real binary in a pseudo-terminal (stdlib only) and checks alt-screen enter/leave, cursor, tty-mode restore, resizes, overlays and colour-free output | The spec asks for a terminal-restore smoke test; TestBackend cannot see escape sequences or tty state | Linux/macOS only. Colour checks parse SGR parameters (cursor moves such as `ESC[38;1H` are not colours). |
| ADR-054 | Accepted | `rust-version` is 1.95 (was an untested 1.85) | `sysinfo` 0.40 requires it; checked by building on 1.85–1.90 (rejected) and 1.94 (rejected) vs 1.95 (passes) | Users need a recent toolchain; older ones need an older `sysinfo`. CI has an MSRV job that reads this field. |
| ADR-055 | Accepted | `publish = false` in `Cargo.toml` and license holder "The systui authors" | No repository URL, crate-name decision or legal name was given; both are one-line changes | Remove `publish = false` and set `repository` when ready. |
| ADR-056 | Accepted | README screenshots are text captures of the real renderer with real data (only the host name replaced), produced by `examples/screenshot.rs` | Spec: captures from the implemented UI, not fabricated | Contain real process/interface names of the capture machine; colour is not shown. |
| ADR-057 | Accepted | Tests that touch real Docker must not choose an existing container as the target of a mutating action | A flaky test picked "the first running container" while the user's stack was shutting down; one regression away from stopping a real container | The rule is written at the bottom of `tests/docker_m6_tests.rs`. |
